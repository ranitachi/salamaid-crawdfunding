## Bagian 1 — Bersihkan A8

Target:

- Seluruh `PayoutOperationsTest` lulus.
- Full test suite tidak memiliki failure baru.
- Evidence private storage benar-benar berjalan.
- Backward compatibility URL lama tetap tersedia.
- Tidak ada IDOR pada download evidence.

### 1. Form Request

File: `Modules/Operations/App/Http/Requests/MarkPayoutPaidRequest.php`

Pastikan:

- Mendukung upload file private baru.
- Mendukung `evidence_url` lama.
- Evidence file dan evidence URL tidak boleh sama-sama wajib.
- Salah satu evidence harus tersedia.
- File hanya menerima `jpg/jpeg`, `png`, dan `pdf`.
- Batas ukuran file jelas dan tervalidasi.
- Validasi tidak menerima path traversal.
- MIME type client tidak dipercaya tanpa pemeriksaan server.

Gunakan field yang jelas, misalnya `evidence_file` dan `evidence_url`. Jika format `evidence` sudah digunakan oleh test atau UI, tetap dukung dengan kontrak konsisten dan dokumentasikan.

### 2. Controller

File: `Modules/Operations/App/Http/Controllers/Admin/PayoutAdminController.php`

Pastikan:

- Controller menggunakan method evidence dari Form Request.
- Tidak lagi mengirim `validated('evidence_url')` ke service jika service mengharapkan array.
- File upload disimpan ke private disk sebelum payout ditandai paid.
- Tersedia method download evidence.
- Download melewati policy.
- Download hanya mengambil `evidence_path` milik payout tersebut.
- File hilang mengembalikan 404.
- Tidak ada akses langsung ke public root.

Tambahkan endpoint:

```text
GET /admin/payouts/{payout}/evidence
Name: admin.payouts.evidence.download
```

### 3. Payout Model

File: `Modules/Operations/Entities/Payout.php`

Pastikan field berikut tersedia pada fillable/casts bila diperlukan:

```text
evidence_path
evidence_mime
evidence_size
```

Data lama dengan `evidence_url` harus tetap dapat ditampilkan.

### 4. Policy

File: `Modules/Operations/Policies/PayoutPolicy.php`

Tambahkan policy:

```php
downloadEvidence(User $user, Payout $payout): bool
```

Akses minimal membutuhkan permission `payouts.manage`. User tidak boleh mengunduh evidence payout lain melalui manipulasi ID.

### 5. Payout Service

File: `Modules/Operations/App/Services/Admin/PayoutService.php`

Pastikan:

- Private file menyimpan `evidence_path`, `evidence_mime`, dan `evidence_size`.
- URL lama menyimpan `evidence_url`.
- Private file tidak menghasilkan URL publik.
- Balance validation tetap dijalankan.
- Audit state transition tetap berjalan.
- Data sensitif tidak masuk audit log.

### 6. View payout

## Bagian 2 — Selesaikan A12

A12 mencakup hardening, QA, dan release readiness.

### 1. Dependency audit

Jalankan `rtk composer audit`. Jangan melakukan upgrade dependency besar tanpa alasan dan test. Dokumentasikan advisory, package terdampak, kemungkinan perbaikan tanpa breaking change, dan rekomendasi mitigasi.

### 2. Authorization dan route audit

Periksa semua route admin dengan `rtk php artisan route:list`.

Pastikan:

- Semua route admin berada dalam middleware `auth` dan `admin`.
- Route sensitif memiliki `admin.permission`.
- Object action memakai policy.
- Tidak ada endpoint perubahan status tanpa authorization.
- Route export memiliki permission.
- Route download private file memiliki policy.

Tambahkan test route tanpa middleware untuk area sensitif.

### 3. Security testing

Tambahkan atau perbaiki test untuk:

- IDOR pada campaign, organization, donation, payment, payout, transparency, notification, dan evidence.
- Privilege escalation antar-role.
- Reviewer tidak dapat mengakses finance action.
- Support tidak dapat melihat data sensitif.
- CSRF pada semua POST/PATCH/DELETE.
- Mass assignment.
- XSS pada campaign title/description, organization name, campaign update, rejection reason, audit reason, dan notification message.
- Password, token, API key, signature, dan payment payload tidak muncul pada response, log, audit, atau export.

Jangan mengubah `app/Models/User.php` kecuali benar-benar diperlukan dan didokumentasikan.

### 4. Input dan output hardening

Periksa Form Request seluruh area admin, validasi tanggal/range, validasi upload/private storage, CSV export dari formula injection, escaping Blade, dan penggunaan raw HTML.

### 5. Query dan performance

Audit query admin untuk N+1, pagination, eager loading, query tanpa batas, export terlalu besar, dan dashboard aggregate. Tambahkan test atau query assertion untuk area yang mudah mengalami N+1. Jangan menambahkan cache jika menyebabkan data antar-permission tercampur.

### 6. Queue, scheduler, dan webhook

Pastikan job memiliki retry/backoff, idempotent, failed job tercatat, duplicate webhook aman, queue terdokumentasi, dan payment sync tidak dapat dipicu tanpa permission. Scheduler pending payment harus didokumentasikan bila belum tersedia.

### 7. Production configuration

Periksa `.env.example` dan dokumentasikan:

```text
APP_ENV
APP_DEBUG
APP_URL
DB_*
QUEUE_CONNECTION
MAIL_*
FILESYSTEM_DISK
MAYAR_ENVIRONMENT
MAYAR_API_BASE_URL
MAYAR_TIMEOUT
MAYAR_CONNECT_TIMEOUT
ADMIN_NOTIFICATION_EMAIL_ENABLED
ADMIN_DASHBOARD_PAYOUT_PENDING_DAYS
```

Jangan menambahkan credential asli ke repository.

### 8. Error page dan operational readiness

Pastikan tersedia atau dokumentasikan 403, 404, 419, 429, 500, dan maintenance response. Periksa logging secret, private storage, queue worker, migration, backup/restore, dan deployment checklist.

### 9. Dokumentasi

Perbarui:

```text
docs/admin-a8.md
docs/tahapan-admin.md
docs/pembagian-tugas-admin.md
```

Update status hanya berdasarkan bukti test. A8 tidak boleh ditandai `DONE` jika masih ada failure.
